## 4. 표결 API에서 발견한 불일치

최신 의안 3건의 개인별 표결을 `pSize=1000`으로 조회했다. 각 응답의 전체 건수와 실제 반환 건수는 모두 283건이므로 단순히 다음 페이지를 빼먹은 상황은 아니다.

| 의안번호 / 일자 | 총계 API 재적 | 총계 찬성/반대/기권 | 개인 API 찬성/반대/기권/불참 | 개인 API 참여 합계 | 총계와 차이 |
| --- | ---: | --- | --- | ---: | ---: |
| 2221432 / 2026-09-17 | 299 | 198 / 2 / 4 | 186 / 2 / 4 / 91 | 192 | 12표 부족 |
| 2221431 / 2026-09-17 | 299 | 154 / 49 / 1 | 144 / 47 / 1 / 91 | 192 | 12표 부족 |
| 2221430 / 2026-09-17 | 299 | 157 / 37 / 4 | 147 / 35 / 4 / 97 | 186 | 12표 부족 |

각 표본의 개인 API 고유 의원코드도 283개이며, 당시 현역 명단 대비 동일한 16개 코드가 조회되지 않았다. API로 반환된 코드는 모두 현역 명단에 연결됐다.

### 필터·원문 교차 확인

- 의안 2221432에 `MONA_CD=QHL3248U`(김남국)를 지정해도 `INFO-200`, 0행.
- 같은 의안에서 `MONA_CD=T2T8225E`(강경숙)는 찬성 1행으로 정상 조회.
- 의원이력에서 김남국의 제22대 재임 시작일은 2026-06-04로 표시돼, 이 표본의 표결일보다 이전이다.
- **국회 웹페이지 표결 탭에는 김남국이 찬성 명단에 있다.** 웹페이지 명단은 찬성 198명, 반대 2명, 기권 4명으로 총계와 일치한다.
- 비교용 과거 의안 2205421(2024-11-14)은 개인 300행, 찬성 253·반대 2·기권 9·불참 36으로 총계와 일치했다.

따라서 모든 표결 API가 틀리다는 결론도, 최신 3건만의 문제라는 결론도 낼 수 없다. 신규 의원 연계 누락 가능성이 있으나 원인은 미확정이다.

### 평가에 적용할 처리 방향

1. 안건별로 개인 합계와 공식 총계를 대조한다.
2. 조회되지 않는 의원을 불참 0점으로 처리하지 않는다.
3. 불일치 안건은 원천 웹페이지로 보완하고, 출처·수정 이력을 남기는 방식을 검증한다.
4. 웹페이지 이름만으로 식별하지 않는다. 동명이인은 의원 페이지 링크와 재임 이력까지 확인한다.
5. 모든 안건을 일률적으로 제외해 편향된 참여율을 만들지 않는다. 전체 기간의 누락 범위·보완 가능성을 먼저 확인한다.

표결 웹페이지 탭은 화면 내부 POST 조회로 읽었다. 공식 Open API와 다른 경로이므로 운영 연동의 안정성과 변경 감지는 별도 검토가 필요하다.

### 신원 연결의 실제 예외

본회의 XLSX의 단순 한글명/한자명 대조에서 299행 중 297행은 현역 명단의 단일 코드에 대응했고, 2행은 추가 확인이 필요했다.

- 현역 API에 한글 이름이 '박지원'인 의원 2명이 서로 다른 코드·한자명·지역구로 존재한다. 파일에서는 한 행을 '朴芝源'으로 구분한다. 이름만 키로 쓰지 않는다.
- 출결 파일에 있는 이해민은 조회 시점 현역 명단에는 없고 역대 포함 API에 있다. 출결 대상 시점과 현재 명단의 시점이 다르다.
- 파일에 보궐선거·비례승계 메모와 서로 다른 누적 회의일수가 있어, 중도 입성자를 모두 같은 분모로 평가하면 안 된다.

## 6. 재임 이력 해석

강경숙 표본에서 의원 재임은 `2024.05.30 ~ `, 교육위원회 이력은 `2024.06.10 ~ 2026.05.29` 및 `2026.06.30 ~ ` 등으로 제공됐다.

김남국의 의원이력 조회에서는 제21대·제22대 행 모두 `UNIT_CD=100022`였다. 명세가 설명하는 이 값은 '최종 대수'이므로 **이력 개별 행의 대수로 사용하면 안 된다.** 개별 이력의 `PROFILE_SJ`와 `FRTO_DATE`를 함께 해석해야 한다.
