- D1에 `member_committee_attendance` 테이블과 `member_scores.committee_attendance_percentile`, `score_runs.committee_attendance_weight` 컬럼을 추가함.
- 2단계 산식을 입법 40% · 표결 35% · 본회의 출석 15% · 위원회 출석 10%로 정함. 위원회 출석은 회의일 단위가 아닌 월별 집계이고 원자료 불일치 4건이 남아 있어 본회의 출석보다 낮은 비중을 부여함.
- 위원회 자료가 없는 의원(김형연, 최근 임기 시작)은 위원회 10% 비중을 나머지 세 항목에 비례 재분배해 계산하고, 조용히 0점 처리하지 않음.
- `compute-scores.cjs`를 재사용해 새 `score_runs` 행(`stage2-2026-10-01`)을 추가함. 과거 1단계 결과(`stage1-2026-10-01`)는 삭제하지 않고 기록으로 남김.
- 전체 실적표·의원 상세·비교 화면에 위원회 출석 열/항목을 추가해 배포함. 여전히 `gradeDatasetApproved: false`.

## 3단계 산식: 겸직 기간 처리 — 2026-10-08

- 사용자가 장관·총리·국회의장 겸직 의원이 상대적으로 불리하다는 문제를 제기했고, 비판에 과학적·논리적으로 방어할 수 있는 방식으로 산정하기로 합의함.
- 국회의장·국무총리·국무위원 겸직 기간의 표결·본회의·위원회 기록과 재임일수를 분자·분모에서 함께 제외(경계일 포함). 남은 관찰 기간 180일 미만이면 "겸직으로 평가 유보".
- 국회부의장은 사용자 결정에 따라 표시만 하고 정상 평가.
- 당직(당대표·원내대표 등)과 정당의 집단 표결 불참은 자발적 정치 선택이므로 보정하지 않음.
- 제외 건수는 표결 API와 출결 원본(3차 검증과 sha256 일치)에서 날짜별로 다시 계산하고, 의원별 전체 합계가 D1과 일치하지 않으면 계산을 멈추도록 함. 무보정 시 2단계 결과와 299명 전원이 동일함을 회귀 확인.
- 점수 결과를 D1이 아닌 `app/lib/score-run.js`로 코드와 함께 버전 관리하기로 함(Git 반영만으로 배포되고 화면·점수 불일치 방지).
- 메인 상단 문구를 시민용으로 바꾸고 산식 버전은 평가 방법 섹션으로 옮김.
- 표시 원칙(사용자 요청): 목록·비교 화면에는 **현재 겸직만** 표시하고, 지난 겸직은 의원 상세 프로필의 경력 줄에만 기간·출처와 함께 적음. 평가 산정(겸직 기간 제외)은 현재·과거 구분 없이 동일하게 적용.

- 무인증 API 조회만으로 전체 데이터 확보가 가능하다는 설명은 부정확했다. 관찰된 응답은 5건과 첫 페이지로 제한됐다.
- API 목록 280개 수집 시도는 동일 5개 반복으로, 전체 목록 수집 성공이 아니었다.
- 비슷한 법안을 같은 날 발의했다는 이유만으로 자동 병합하는 평가 방식은 채택하지 않는다.
- 선거기간에 랭킹을 일괄 중단해야 한다는 이전 설명은 법적 근거와 적용 조건을 확인하지 않은 단정이었다. 확정 운영 정책으로 채택하지 않는다.
