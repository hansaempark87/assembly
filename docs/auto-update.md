# 자동 갱신

2026-10-09부터 데이터는 매주 월요일 06:00(KST)에 GitHub Actions(`.github/workflows/data-update.yml`)가 자동으로 갱신한다. 사람이 손대는 것은 자동 규칙으로 결정할 수 없는 경우뿐이다.

## 흐름

```
fetch.py  → 국회 공개 자료 수집, app/data/source/ 갱신
build.py  → 원자료 → 의원별 집계 → 겸직 제외 → 협치 가산점 → 점수·등급
            → 표결 페이지 자료(public/vote-data/), 의원별 법안·표결 기록(public/bills/)
check.py  → 현재 공개본(main)과 비교 검증
  ├ 모두 통과   → main에 커밋 → Cloudflare Pages 자동 배포
  └ 확인 필요   → 반영하지 않음. data-review/<날짜> 브랜치 + GitHub 이슈(메일 알림)
```

수동 실행: GitHub → Actions → data-update → Run workflow. 국회 API 키는 저장소 시크릿 `ASSEMBLY_API_KEY`에만 있다.

## 집계 규칙

- **표결**: 임기 중 열린 모든 본회의 표결이 분모, 찬성·반대·기권이 참여. 의석이 바뀐 날의 표결은 모두에게서 뺀다(기존 76건).
- **출결**: 본회의·위원회 모두 파일에 인쇄된 공개 합계를 쓴다. 날짜별 표시와 합계가 다르면 공개 합계를 따르고, 갱신 요약에 기록한다.
- **법안**: 법안 기준일까지 발의된 대표발의 법안, 처리 결과도 기준일 기준.
- **재임일수**: 법안 기준일까지. 겸직 기간은 진행 중이면 기준일까지 제외.
- **수록 범위**: 표결은 개인별 기록이 공개된 날까지, 출결은 공개된 파일까지. 화면의 평가 방법 페이지에 자동 표시된다.

## 자동 반영을 멈추는 경우

| 검사 | 이유 |
| --- | --- |
| 의원이 새로 들어오거나 빠짐 | 임기 시작·종료일과 공정성 처리를 사람이 정해야 함 |
| 표결의 개인별 찬성·반대·기권 수 ≠ 공식 집계 | 원자료 오류 가능 |
| 표결 당일 재임 의원 수 ≠ 공식 재적 수 | 명단 변동을 놓쳤을 가능성 |
| 의원 임기 시작일과 같은 날의 표결 | 분모 포함 여부를 회의록으로 판단해야 함 |
| 출결 파일의 이름을 의원 한 명에 연결할 수 없음 | 동명이인·오기 |
| 이미 반영한 회기·월의 출결 파일이 다시 게시됨 | 과거 수치가 바뀔 수 있음 |
| 원천이 기존보다 적은 기록을 반환 | 일부만 응답했거나 삭제 |
| 어떤 의원이든 누적 수치(표결 대상, 출석일, 발의 건수 등)가 줄어듦 | 기록은 늘기만 해야 함 |
| 수록 기준일이 뒤로 감, 등급 대상이 4명 이상 줄어듦 | 이상 징후 |
| API가 새 데이터를 읽지 못함 | 배포 전 점검 |

멈추면 화면은 직전 데이터 그대로 유지된다. 이슈에 이유와 변경 내용 비교 링크가 남는다. 판단이 필요한 기준을 새로 정하면 `app/public/data-notes.json`(/notes)에 공개한다.

## 사람이 맡는 일

- 겸직(의장·총리·장관) 임명·퇴임: `app/data/member-roles.json`에 날짜와 출처를 넣으면 다음 갱신부터 반영.
- 새 의원(보궐선거·승계): `members.json`에 임기 시작일과 함께 추가.
- 원자료 모순의 새 유형: 기준을 정해 /notes에 공개.
