## 1. 검증 범위

`ncocpgfiaoituanbr`의 `AGE=22` 조회 결과 1,847행을 1,000건씩 두 페이지로 읽었다. 고유 `BILL_ID`도 1,847개였다. 각 의안에 대해 `nojepdqqaweusdfbi`를 조회해 개인별 찬성·반대·기권 합계를 총계와 대조했다.

이 문서의 '전체'는 **조회 시점 해당 API 목록의 전체**를 뜻한다. 국회에서 진행한 모든 표결, 무기명 표결, 재표결 각각이 빠짐없이 포함됐다는 독립 검증은 아직 하지 않았다. 하나의 의안이 여러 번 표결된 경우의 이벤트 식별 방식도 별도 확인 대상이다.

제공 목록의 날짜 범위는 2024-07-04~2026-09-17이다. 법률안 1,673건 외 결의안 47, 규칙안 3, 승인안 11, 중요동의 21, 예산안 59, 동의안 31, 결산 2건이 포함된다. 최종 평가에서 포함할 의안 종류는 아직 확정하지 않았다.

## 3. 총계가 맞아도 누락이 있을 수 있다

당일 재임자 명부를 시작일·종료일 포함으로 임시 구성하여 개인 API의 의원코드와 비교했다.

- 총계는 일치하지만 재임자 명부의 의원 행이 없는 안건: **338건**
- 총계 불일치 또는 명부 차이로 원문 추가 확인 대상으로 선정: **814건**
- 총계·명부 수·의원코드 집합까지 일치한 안건: **1,033건**

338건에는 실제 데이터 연계 누락뿐 아니라 날짜 단위 재임 이력으로 해결할 수 없는 경계일 사례도 포함된다. 이 수를 모두 원천 오류로 단정하지 않는다.

예를 들어 이소희 코드 `MRS4949T`는 재임 시작일 이후 API 대상 안건 791건에 행이 없었다. 참여하지 않은 안건에서는 해당 행이 없어도 찬반·기권 총계가 맞을 수 있다. **합계 검사와 명부 검사를 둘 다 통과해야 한다.**

또한 의안 [2215128](https://likms.assembly.go.kr/bill/billDetail.do?billId=PRC_G2Z5L1L1C2F1O1S6A0I6O4J4T5B8G3)은 공식 총계가 찬성 195·반대 0·기권 2인 반면 개인 API는 찬성 196·반대 0·기권 1이다. 참여자 수 197만 확인하면 놓치는 사례다.

## 4. 제22대 재임자 명부

### 사용 자료

- `nexgtxtmaamffofof`: 현역 의원의 이력 610행
- 이 중 `PROFILE_SJ`가 제22대인 이력 299행 / 고유 코드 299개
- `nfzegpkvaclgtscxt`, `PROFILE_UNIT_CD=100022`: 전직 의원의 제22대 이력 22행
- 합친 제22대 이력: **321명 / 고유 코드 321개**
- `ALLNAMEMBER`의 역대 포함 인적 정보: 3,296행. 위 321개 코드는 모두 연결됨

기간 문자열 321행은 모두 날짜 형태로 해석됐고, 현역 299명 중 제22대 이력이 없는 의원은 없었다. 전체 표결에서 받은 개인 API 코드도 모두 이 명부에 연결되었으며, 날짜 포함 기준 재임 기간 밖의 기록은 발견되지 않았다.

이 검사는 API 간 연결 검사다. 모든 취임·퇴임일을 관보·회의록 등 독립 원문과 대조했다는 뜻은 아니다.

### 재임 이력의 '최종 대수' 주의

현역 이력 API의 `UNIT_CD`는 명세상 최종 대수다. 이 값만으로 제22대 이력 행을 추리지 않고 `PROFILE_SJ`와 `FRTO_DATE`를 함께 사용했다. 전체 결과에서 제22대 위원회 경력은 1,696행 / 현역 의원 299명으로 확인했으며 기간 문자열 결측·동일 행 중복은 발견하지 않았다. 전직 의원의 위원회 이력은 이번 추가 검증 범위 밖이다.

## 6. 출결의 동명이인·과거 의원 연결 해결

- 회의일 기준 재임자는 299명.
- 이해민은 제22대 재임 종료일이 2026-08-30으로 제공돼 두 회의일에 포함된다. 현재 명단에 없다는 이유로 과거 출결을 버리지 않는다.
- 이름 '朴芝源'을 코드 `H7X3372O`에 먼저 연결한 뒤, 같은 표의 한글 '박지원' 행을 나머지 코드 `8BF5855P`에 연결했다.

이는 해당 파일과 해당 명부에서 명시적 한자명·재임 기간·표 내 일대일 대응을 이용한 해결이다. 다른 파일에 이름 중복이 생겨도 임의로 남는 이름을 배정하지 않는다.

## 7. 원문 보완 원칙

국회 상세 페이지에서 실제 사용하는 표결정보 조회 방식으로 찬성·반대·기권 명단을 읽고, 이름·의원 링크·당일 명부를 연결한다. 재임자가 단 한 명으로 대응하는 이름만 자동 연결하고 동명이인은 공식 코드 확인을 추가한다.

보완 검사는 다음 조건을 함께 확인한다.

1. 원문 명단의 찬성·반대·기권 각각의 수가 총계와 일치
2. 이름과 링크가 당일 명부의 의원코드에 연결됨
3. 원문 명단의 의원코드가 중복되지 않음
4. API의 기존 참여자와 원문 결과 사이 충돌 또는 원문 누락이 없음
5. 당일 명부 수와 총계 재적수가 일치

원문에 없는 의원을 곧바로 'API상 불참'으로 덮어쓰지 않는다. 완전한 참여자 명단과 확정 재임 분모를 전제로 계산한 비참여라면 **원문 명단 기반 파생값**이라고 구분하고, 미확인 상태는 그대로 남긴다.

### 보류 77건의 구성

- 76건: 앞서 기술한 3개 재임 경계일의 명부 수 차이. 웹 참여 명단의 총계·신원은 맞지만 적격 분모가 미확정.

API 자체 검사 통과 1,033건과 원문 보완 조건 통과 737건을 합치면 1,770건(95.83%)이다. 1,033건 모두를 개별 웹페이지와 대조한 것은 아니며, 숫자가 일치해도 사람별 결과가 맞바뀐 오류까지 배제한 검증은 아니다. 77건을 빼고 바로 의원별 참여율·등급을 계산하면 기간과 의원별 편향이 생길 수 있어 최종 평가 자료로 확정하지 않는다.

원문 데이터는 조회 중에 수정될 수 있다. 이번 검증은 일회성 시점 비교이며, 배포 데이터는 원본 해시·수집 시각을 보존해 재검증할 수 있어야 한다.

## 9. 후속 회의록 확인

제22대 국회회의록의 해당 본회의 원문을 추가 대조했다.

- 2024-12-12 제419회 제2차: 개의 후 보고에서 조국 의원의 같은 날 대법원 확정판결에 따른 퇴직을 명시한다. 표결 총계 재적 299와 일치하므로 이 회의 2건의 분모에서 제외한다.
- 2025-07-23 제427회 제2차: 보고사항은 임광현 의원이 2025-07-22 궐원됐다고 명시한다. 이주희 의원의 제22대 이력 시작일은 2025-07-23이지만 해당 회의록 출석·투표 의원 명단에 이주희가 없고 총계 재적은 297이다. 같은 날 승계 효력의 정확한 시각까지 확인한 것은 아니므로 이 회의 21건에서는 평가 분모에 포함하지 않는 보수적 규칙을 제안한다. 제427회 출결 XLSX도 2025-07-10·23에는 이주희를 `-`, 2025-08-04에는 출석으로 표시한다.
- 2026-03-12 제433회 제1차: 개의 후 보고에서 양문석 의원의 같은 날 상고 기각·판결 확정을 명시한다. 표결 총계 재적 295와 일치하므로 이 회의 53건의 분모에서 제외한다.
- 의안 2215128: 회의 중 의장이 발표한 결과는 찬성 195·기권 2지만, 회의록 끝의 개인 명단은 찬성 196·기권 1이며 정춘생 의원을 기권에서 찬성으로 정정했다고 적었다. API와 웹 명단도 196/1이다. 따라서 **개인별 최종 결과는 정정된 196/1 명단을 우선**하고, 총계와의 불일치 및 근거를 표시한다.

이 기준을 적용하면 이전의 보류 77건 모두 처리 규칙을 정할 수 있다. 다만 2025-07-23의 의원 승계 시각은 회의록에서 확인되지 않아 별도 표시하고, 이 규칙은 평가 산식 확정과 전체 데이터셋 생성 과정에서 회귀 검증한 후 최종 승인한다.

## 10. 다음 단계 및 평가 설계에 반영할 내용

- S/A/B/C/D 상대평가와 시민 평가 제외 방향은 유지.
- 표결 누락을 0점으로 바꾸거나, 보완 없이 해당 의원의 분모만 줄이지 않음.
- 상대평가 전에 의원별 자료 커버리지와 적격 분모를 확정.
- 날짜 경계·의원 식별·원문 충돌 건은 검토 목록으로 분리.
- 국회 웹페이지는 공식 API가 아니므로 구조 변경·파싱 오류를 감지할 필요가 있음.
- 위 검증은 수집·평가 서비스 구현이 아니라 원천자료 검증이다. 제품 스택은 미선정.

남은 작업:

1. 출결에서 발견된 원자료 합계 불일치 처리 및 전체 신원 연결.
2. 재표결·의안 종류 포함 기준, 공동대표발의·대안 점수 귀속 기준 확정.
3. 전체 데이터셋 생성 시 77건 처리 규칙의 회귀 검증.
4. 분모와 커버리지 확정 이후 상대평가 산식 시뮬레이션.

[요약 증거 JSON](vote-audit-evidence-2026-10-01.json)과 [안건별 검사 결과 CSV](vote-audit-results-2026-10-01.csv)를 함께 저장한다. CSV의 `api_only_pass`와 `web_repair_pass`는 검증 방식이 다르며 `grade_ready`를 의미하지 않는다.

CSV는 1,847개 의안의 개별 집계·검사 상태를 기록한다. `api_sample_sha256`와 `web_sample_sha256`는 임시 작업 공간에 보관한 키 없는 정규화 JSON 표본 파일의 해시이며, 원본 HTTP 응답 바이트의 해시는 아니다. `web_checked`는 814건의 추가 대조 대상 여부다. 별도 7건의 탐색 표본 중 추가 대조 대상에 들지 않는 것은 이 열의 집계에 포함하지 않는다. 해시만으로 원자료를 복원할 수는 없다.
